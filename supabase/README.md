# Supabase backend (free tier)

Everything the app needs server-side is in two files:

| File | What it does |
|---|---|
| `migrations/20260925000001_init.sql` | Schema, Row Level Security, triggers, and RPCs (`place_order`, `validate_coupon`, `product_reviews`, `my_orders`, `delete_my_account`) |
| `seed.sql` | Catalog, reviews, coupons, broadcast notifications — generated by `scripts/generate_fixtures.py` from the same data as the offline fixtures |

## Set up (≈ 5 minutes, no credit card)

1. Create a project at [supabase.com](https://supabase.com) → **New project** (Free plan).
2. **SQL Editor → New query** → paste `migrations/20260925000001_init.sql` → **Run**.
3. New query → paste `seed.sql` → **Run**.
4. **Authentication → Sign In / Providers → Email**: for a demo, turn **Confirm email** off
   (the app also handles it on: it tells the user to check their inbox).
5. **Project Settings → API**: copy the project URL's host and the **publishable (anon)** key into
   `Config/Supabase.local.xcconfig` (copy it from `Config/Supabase.local.example.xcconfig`):

   ```
   SUPABASE_HOST = abcdefghijkl.supabase.co
   SUPABASE_PUBLISHABLE_KEY = sb_publishable_…   (or the legacy "anon" JWT)
   ```

   Never use the `service_role` / secret key in the app.
6. Build and run. Settings → *Data & Sync* shows `Supabase · <host>`.

With the CLI instead: `supabase link --project-ref <ref> && supabase db push` then run `seed.sql`.

## Verify Row Level Security

In the SQL editor, impersonate a user and try to read someone else's data:

```sql
-- As an anonymous client: catalog yes, carts no.
set local role anon;
select count(*) from public.products;     -- 23
select count(*) from public.cart_items;   -- 0 (RLS hides every row)
select * from public.coupons;             -- permission denied
```

## Free-tier notes
- Projects pause after 7 days without activity — resume from the dashboard in one click.
- Built-in email sending is rate-limited (a few per hour); keep "Confirm email" off for demos or
  add a free SMTP provider.
